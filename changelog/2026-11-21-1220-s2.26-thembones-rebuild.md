## What was done

- Copied the ThemBones generator dataset (v2) into `third_party/`, unchanged; all files match its
  `GENERATORS_MANIFEST.sha256` (only Kaggle's `dataset-metadata.json` is absent). Scanned the code for network and
  destructive shell use: only the `VERIFY=1` branch of `f9_i1_stack.sh` uses ssh (the team's remote boxes), never run.
- `setup_sandbox.sh` lays the folders out as their README asks (the only edit: the `<HOME>` redaction undone).
- invsqrt: their one-command pipeline. Two published inputs are missing: `s18/cub/m9dev.json` (the FC18-M9 device,
  config key `_fc18m9`) and the tree `s18/srcR`; also fc18_M's emit, used by the first all-input check.
  `build_invsqrt.sh` removes the key (the generator takes its built-in m9 branch), points `fc2_src` at `srcM` (as the
  q18 recipe does) and makes fc18_M's emit with the same emit command. First attempts failed on a symlinked
  interpreter (the venv's site-packages are only seen when `~/qcc/.venv` is the venv itself) and on the missing files.
- Chemistry: the 15 loaders rebuilt from their `.kmx`. The assembly and gauge tools their README names
  (`chem_c3_entry_raw.py`, `lead_gauge.py`) are not in the dataset; the table and `submission.npz` are carried data.
- dqi: the ThemBones chain cannot run (missing `idle_l9r4dp_902.txt`, `spec_k1.txt`, `jt_tensors_r54c.json`; the team
  never rebuilt its file A either). Used tonylica's builder instead (the board dqi file). The permission system first
  blocked running this downloaded builder; the user approved it.
- Checked that the versioned scripts reproduce the results from a fresh sandbox.

## Why

Plan M2.F: a reproducible source base at the public level, required for prize eligibility and for every later step.

  their own tools (`invsqrt_fc_s18m9frame.py`, `invsqrt_fc_s18m9q.py`); the three affine forms are not on record.
- Open: tonylica's dataset (101 MB, 90 MB of dqi stages) is not yet in the repo; for a prize submission the source
  must be in our repository (user decision on repository size).
